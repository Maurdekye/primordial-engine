44331596600 -- pe-app's bin test the_agent_is_named_by_agent_name_or_else_by_its_command (added by 490d659e) asserted that the command C:\tools\claude.exe names the agent claude; off Windows a backslash is not a path separator, so file_stem kept the whole string and the test failed on linux-x64, linux-arm64 and macos-arm64 (windows-x64 passed). Fixed in the landing that adds this line: that case runs only on Windows, and a tools/claude.exe case runs everywhere.
44380490660 -- pe-replica's test lamp::a_script_event_reaches_the_view_and_a_fault_stops_the_script failed on macos-arm64 only (the other three passed): "no module at .../target/tmp/scripts/wasm32-unknown-unknown/release/tally.wasm". It and the_logic_runner_conforms_where_its_copy_in_skip_fires each built pe-logic's tally script into the same target folder at the same time. Cargo re-links a crate's output to its uplifted path on every run, a fresh one included, and on macOS it copies the file there instead of hard-linking it, removing the old copy first, so one test's cargo could take tally.wasm away while the other test read it; on Linux and Windows the hard link makes both paths one file and cargo skips the step (cargo 1.99.0 5f94df478: compiler/mod.rs link_targets, cargo-util paths.rs _link_or_copy). A race between two tests, not in the product: pe-app's build service takes one build at a time (its turn gate, builds.rs). Fixed in the landing that adds this line: pe-replica's tests build tally once per process, as they already built the lamp.
45382142620 -- pe-app's test capture::tests::the_ball_pit_is_captured_headless_through_a_software_adapter (its event check added by 2f4c751c, 1.3) read the headless thread's capture events right after the API's refusal of the second order, but the server answers that refusal inside serve() and the thread records the events only after serve() returns, so on windows-x64 the third event (Queued) wasn't in yet; the test now waits up to 10 s for it
46115594482 -- two tests added by 874d862d (the in-game join) read the process list the Windows way. On linux-x64 and linux-arm64, pe-logic's build::tests::a_killed_build_takes_its_whole_process_tree said "the grandchild outlived the kill": its running() ran sh -c "pgrep -f 'sleep N'", and that sh's own command line matched, so the grandchild always looked alive. On macos-arm64, pe-app's tests/sessions.rs threads() read /proc, which macOS lacks. Fixed with this line: the pattern is [s]leep N, and macOS counts threads with ps -M.
