# Tier 1 of the landing checks, by path (docs/landing-gates.md, "Tier 1"). scripts/tier1.sh reads this file from
# the landing's base: a landing whose diff touches a path a check names runs that check's command, from the root
# of a checkout of the landing, under the build-slot wrapper. A change here applies from the next landing.
#
#   check <name>       starts a check
#     why <text>       the reason, for whoever reads a failure (more lines add up)
#     when <glob>...   git pathspecs with glob magic: ** spans folders, and **/x matches x at the root too
#                      (more lines add up)
#     all <glob>...    when the diff touches one of these, {crates} is every workspace member (more lines add up)
#     needs <text>     what the command needs installed, shown before it runs
#     skip <package>...  never put into {crates} (more lines add up)
#     run <command>    one shell command line, run with bash -c. {crates} in it becomes -p <package> for each
#                      workspace member whose folder holds a path that triggers the check; with none left, the
#                      check has nothing to run
#     expect <regex>   an extended regex that a line of the command's output must match for the check to pass,
#                      besides exit 0: a test filter that matches no test (renamed, ignored) then fails
#
# Lines starting with # are comments. A check's command runs the landing's own code: a landing that changes what
# a check runs (its test, or the files the test reads) changes the check, and is read as such. A landing whose
# own copy of this table is malformed fails, since that copy would stop every landing after it.
