# The native-code allow file: every exception the landing gate accepts to the "100% Rust" ruling (D1),
# each with its reason. Read by scripts/audit_native.py --check, which scripts/gate.sh runs on every landing.
#
# D1 (user, 2026-10-30 08:28Z, md35ba688f6b4): "want 100% rust": no C/C++ code compiled into the engine.
# OS, driver and runtime boundaries are unavoidable but must be dynamically loaded system components, not
# vendored C (design 20.1). Rust inline assembly is allowed (design 20.2, settled 19:11Z as recommended).
#
# Line kinds (# starts a comment; every line but `target` needs a reason after " -- "):
#   target <triple>                          a triple the gate audits every workspace for
#   targets <folder> <triple>...             other triples for the workspaces under <folder>
#   exclude <folder> -- <reason>             the gate skips the workspaces and crates under <folder>
#   class <class> -- <reason>                accepts every package of <class> (classes: audit_native.py)
#   allow <package> <version> <class> [with=<f,...>] [without=<f,...>] [in=<folder,...>] -- <reason>
#       accepts one package (version: a glob, such as 1.* or *) when the audit puts it in <class>.
#       with= and without= name features that must be on, or off, in every build of it: the workspace
#       as a whole and each crate built on its own (`cargo build -p`), whose features are unified over
#       that crate's graph only. in= limits the line to the workspaces under those folders.
# A package the audit flags, and no line accepts, fails the gate. To accept one, add a line with the
# reason and its evidence; the landing's reviewer approves the line with the change.

# Single packages.
allow blake3 1.* compiles-native with=pure -- with `pure` its build.rs takes the Rust-intrinsics paths and compiles no C or asm (blake3 1.8.7 build.rs:343-371; design 16.6, 20.3); on x86_64 it still runs the C compiler once to probe AVX-512 flag support (c_compiler_support, build.rs:161-195) and discards the answer, so nothing it compiles is linked
allow wayland-sys 0.31.* links-native with=dlopen -- (matches nothing since M0 archived pe-app's video tool; wgpu-hal brings it back) Linux only, through wgpu-hal in the video tool: with `dlopen` its build.rs returns before calling pkg-config ("Do not link to anything", 0.31.11 build.rs:4-7) and libwayland is loaded at run time, a system library (design 20.1)
allow ash 0.38.* links-native without=linked -- (matches nothing since M0 archived pe-app's video tool; wgpu-hal brings it back) Vulkan bindings, through wgpu-hal in the video tool: its build.rs emits rustc-link-lib=vulkan only with `linked` (0.38.0 build.rs:2-21); without it (`loaded`) the Vulkan loader is loaded at run time (design 20.1)
allow rayon-core 1.* links-native -- `links = "rayon-core"` only stops two rayon-core versions in one build; its build.rs links nothing ("we're not *actually* linking to anything", 1.13.0 build.rs:1-7)
allow wasmtime 50.* compiles-native in=spikes/iter-bench/host -- the iteration benchmark's host (iteration-benchmark 5, D12 evidence) runs guests in wasmtime to compare runtimes; on Linux and macOS wasmtime's build.rs compiles helpers.c whatever the features (design 20.2); a benchmark, never the engine
allow wayland-backend 0.3.* compiles-native without=log -- (matches nothing today; winit brings it, design 20.2) its build.rs compiles its C log shims only with `log` (0.3.17 build.rs:5-12); keep that feature off (design 20.2: "keep wayland-backend/log off; CI checks the resolved features")
allow x11-dl 2.* links-native -- Linux only, through winit in pe-render's window (X11 backend): its build.rs compiles nothing; it only asks pkg-config for each X library's libdir, as a search hint, and emits rustc-link-lib=dl, glibc's libdl (2.21.0 build.rs:35-52); the X11 libraries are dlopen'd at run time (src/link.rs:91), system libraries (design 20.1)
